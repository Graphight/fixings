# ref-links

- Status: Accepted
- Created: 2026-11-13
- Reflects: branch `ref-links`, and a live session on 2026-11-13

## Summary
The `ref-links` mod turns `#N`, `owner/repo#N`, listed Jira keys and bare GitHub PR and issue URLs into links in replies and in typed prompts.

## Context
Replies name tickets, PRs and issues as plain text, so opening one means copying it into a browser.

## Design
- **Replies.** A `ui.render` hook on `AssistantMessage` rewrites the markdown, so `#3` becomes `[#3](https://github.com/<owner>/<repo>/issues/3)`, and passes it on with `next`, so Claude Code, `skins` and `copy-visible` draw the reply as usual.
  GitHub redirects `/issues/N` to `/pull/N` for a pull request, so one URL form covers both.
- **Typed prompts.** `UserMessage.text` is plain text, not markdown, so the hook calls `next` and walks the drawn tree, splitting each `Text`'s strings into strings and `Link` elements.
  This keeps `prompt-tint`'s box. Only typed origins (`composer`, `bridge`, `sdk`) are linked.
- **Repository.** `#N` links to the session repository, read from `$.session.repo()`'s remote in the three GitHub spellings; any other remote leaves `#N` plain.
  `owner/repo#N` links whatever the session's repository is.
- **Jira.** Keys link only for projects in a `projects` option, to `<jiraUrl>/browse/KEY`; both options default to empty, so `UTF-8` and `SHA-256` never link and no employer data sits in the repo.
- **Bare GitHub URLs** draw as `repo#N`, owner dropped.
- **Left alone.** Inline code, fenced blocks, existing markdown links and autolinks; a reference needs a non-word character on both sides.
- **Shape.** One `find` function returns the matches and both hooks share it; see `plugins/ref-links/hooks/register.tsx`.

## Alternatives considered
- One `CLAUDE.md` line asking for full markdown links: skipped. It depends on the model following it every time, and a typed prompt cannot be reached that way.
- Linking every `ABC-123` pattern: rejected, since `UTF-8` and `SHA-256` would link; the `projects` list names what is a project.
- Jira on-hover previews and a link-preview pane: not built; the pane stays in proposal `link-preview-pane`.
- Linking in tool output or slash-command output: not built.

## Consequences & open questions
- An all-digit colour such as `#000000` outside code links as an issue.
- Rewriting the reply's text has a cost under `skins` 0.5.16: its `copy reply` button is built from `e.props.text`, so it copies the markdown links. Accepted rather than drawing the links after `skins`, which would depend on Claude Code's own reply row being walkable, and its prompt row is not.
- Claude Code's own prompt row, without `prompt-tint`, is not a tree the hook can split: in the live check on 2026-11-13 the prompt carried no links alone and all four beside `prompt-tint`. So prompts link only under `prompt-tint`.
- A prompt's links carry no colour of their own, so in Ghostty they show only on cmd-hover.
- A `--plugin-dir` copy linked beside `skins`, `prompt-tint` and `copy-visible`; the order an installed copy needs in `enabledPlugins` is unchecked.
